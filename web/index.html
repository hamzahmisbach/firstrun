How it works

1

A laptop that is not yours

A fresh Linux sandbox is seeded with realistic fake credentials: SSH keys, cloud keys, tokens, a wallet. Every one is a decoy made for this run.

2

The command runs for real

Hidden encoding is peeled off first. Then the command runs exactly as pasted, with every file access, process and connection recorded from outside.

3

Told against done

Fixed rules compare what happened with what you were told. A decoy leaving the sandbox is always malicious, whatever the story said.

What a result does and does not mean

  • Linux commands only. The sandbox is a Linux container; Windows and macOS commands are refused. A script that behaves differently on Windows or macOS is only tested as Linux.
  • 60 seconds, no internet. Every host name resolves to a fake server that records the request and answers nothing useful, so code the command would download is never fetched.
  • Clean is not safe. A clean result means nothing suspicious was seen in this run. It is not a promise that the command is safe on your machine.
FirstRun runs on Vultr Cloud Compute with gVisor sandboxes, Vultr Serverless Inference for unwrapping and explanations, and Vultr Object Storage for reports. Reports are unlisted and kept for a limited time. To have one removed, contact the team listed in the project README.
